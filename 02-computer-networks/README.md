# 컴퓨터네트워크

2026년 1학기 · C++

전송 계층과 라우팅 계층을 각각 직접 구현한 두 프로젝트입니다.
두 과제 모두 정확성뿐 아니라 전송 비용이 평가에 포함되어 최적화가 필요했습니다.

## [적응형 전송기](adaptive-sender)

잡음으로 비트가 뒤집히는 채널에 파일을 손실 없이 전송하되 비용을 최소화하는 과제입니다.
비용은 전송 바이트와 왕복 횟수의 합이며 왕복 한 번이 250바이트에 해당해,
프레임을 잘게 나누면 왕복 비용이, 크게 나누면 재전송이 늘어납니다.

- **훼손 검출**: CRC-32. 비트 단위 계산은 느리므로 256개 항목의 룩업 테이블로 바이트 단위 갱신
- **최적 크기 유도**: 프레임 하나의 기대 비용을 크기와 오류율의 함수로 세워 정리,
  최적 크기를 닫힌 형태로 도출. 남은 미지수는 오류율 하나
- **오류율 추정**: 로그 스케일에 후보 70개를 놓고, 응답마다 각 후보의 로그 우도를 누적한 뒤
  사후 분포의 가중평균을 추정값으로 사용
- **안정화**: 추정값이 프레임마다 변동해 그대로 반영하면 크기가 불안정해지므로,
  새 값을 직전 값과 섞어 목표를 완만하게 이동. 성공 시 절반씩 증가, 실패 시 즉시 절반 감소

## [링크 스테이트 라우터](link-state-router)

각 라우터가 이웃 정보만으로 전체 최단 경로를 산출하도록 구현했습니다.

**정확성**
- 같은 정보가 여러 경로로 돌아 들어와 오래된 메시지가 최신 정보를 덮어쓸 수 있으므로,
  노드마다 시퀀스 번호를 부여하고 최신 번호보다 낮은 메시지는 폐기
- 링크 단절 시 비용을 특수 값으로 표시해 경로 계산에서 제외

**메시지 크기 축소**
- 노드 번호를 고정 크기로 전송하면 노드가 적을 때 앞자리가 0으로 채워지므로,
  전체 노드 수에서 필요한 최소 비트 수만큼만 담도록 비트 단위 버퍼를 직접 구현
- 시퀀스 번호는 가변 길이 인코딩
- 이웃 목록은 이웃이 적으면 번호 나열이, 많으면 비트맵이 작아지므로
  두 방식을 모두 만들어 두고 매번 크기를 비교해 선택
- 양방향 링크 중복을 막기 위해 자기보다 번호가 큰 이웃만 포함
