객체지향 설계와 동시성 처리를 익히는 과제들입니다.

## 좌석 예매 서버

여러 사용자가 동시에 접속해 좌석을 조회하고 예매하는 서버와 클라이언트를 구현했습니다.

- 접속마다 스레드를 생성하면 사용자 증가에 따라 비용이 누적되므로,
  고정 크기 5개를 재사용하는 스레드 풀로 구성
- 좌석 목록은 모든 스레드가 공유하는 자원. 두 사용자가 같은 좌석을 동시에 요청하면
  잔여 확인 시점과 목록 제거 시점 사이에 다른 스레드가 개입해 중복 판매가 발생할 수 있음
- 확인과 제거를 별도 락 객체로 묶어 하나의 임계 구역으로 처리
- 잔여 좌석 목록 전송 부분도 별도로 잠금. 읽는 도중 다른 스레드가 좌석을 제거하면
  일관성이 깨진 상태가 전송되기 때문

검증을 위해 클라이언트도 5개 스레드가 각자 접속해 요청을 보내도록 구성했습니다.

## 차량·계좌 관리 시스템

상속 구조와 사용자 정의 예외를 익히는 과제입니다.

- 승용차와 오토바이의 공통 속성을 추상 클래스로 정의하고 각 차종이 필요한 부분만 확장
- 계좌는 기본 클래스에 입출금을 두고 저축·당좌 계좌가 상속.
  저축 계좌의 이자 지급은 부모의 입금 메서드를 호출해 잔액 변경 로직을 한 곳에 유지
- 중복 등록, 대상 미발견, 형식 오류, 잔액 부족을 각각 별도 예외 클래스로 정의.
  하나로 묶으면 호출부에서 원인을 구분할 수 없기 때문
