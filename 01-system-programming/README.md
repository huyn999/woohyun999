# 시스템프로그래밍

2026년 1학기 · C · Linux

운영체제가 제공하는 자원을 직접 다루는 네 개의 프로젝트입니다.
메모리 할당, 커널 자료구조, 프로세스 제어, 동시성 서버를 각각 구현했습니다.

## [동적 메모리 할당기](malloc)

C 표준 라이브러리의 `malloc`, `free`, `realloc`을 직접 구현했습니다.

평가는 메모리 이용률과 처리량의 가중합인데, 구현의 처리량이 기준을 크게 웃돌아
그 항이 늘 포화되었으므로 점수를 움직일 수 있는 이용률에 집중했습니다.

- 가용 블록을 크기별 12개 클래스로 분리하여 이중 연결 리스트로 관리
- 할당 블록의 풋터를 제거해 블록당 4바이트 절약, 앞 블록 상태는 다음 헤더의 여분 비트로 전달
- 명세가 전역 배열을 금지하여 초기화 시점에 힙 맨 앞 12워드를 확보해 리스트 시작점으로 사용
- 48바이트 이하 요청이 큰 요청 사이에 배치되면 공간이 잘게 나뉘므로,
  살아 있는 소형 블록 수가 32를 넘으면 별도 구역에서만 할당하도록 분리

**결과** 평균 이용률 97.42%, 성능 지수 98점

## [커널 자료구조](pintos-data-structures)

Pintos 커널이 사용하는 리스트, 해시 테이블, 비트맵을 명세만 보고 구현했습니다.

- 리스트: 각 구조체가 연결 정보를 직접 품는 구조로, 연결 정보 주소에서 구조체 시작 주소를 역산
- 정렬, 중복 제거, 최댓값 탐색, 구간 이동 등 20여 개 연산 구현
- 순서를 판단하는 연산은 비교 함수를 인자로 받아 자료형과 무관하게 동작
- 해시 테이블: 버킷별 체이닝, 원소 증가 시 버킷 확장 및 재배치
- 비트맵: 연속된 빈 구간 탐색 시 워드 경계를 넘는 처리

세 자료구조를 합쳐 60여 개 연산을 구현하고, 명령을 입력받아 실행하는 검증 프로그램을 작성했습니다.

## [유닉스 쉘](shell)

내장 명령, 리다이렉션, 파이프라인, 백그라운드 실행, 잡 컨트롤을 3단계에 걸쳐 구현했습니다.

- **파이프라인 파싱**: 명령을 파이프 기준으로 나눠 하나의 버퍼에 파싱하니 앞선 결과가 덮어써짐.
  파서가 버퍼를 수정하며 내부 주소를 인자 배열에 저장하기 때문이었고,
  세그먼트마다 별도 버퍼를 두어 해결
- **시그널 경쟁 조건**: 자식 생성 후 잡 목록 등록 전에 종료되면 핸들러가 없는 항목을 삭제하려 듦.
  `fork` 이전에 `SIGCHLD`를 차단했다가 등록 후 해제
- 시그널은 큐가 아니므로 핸들러에서 종료된 자식을 반복 회수
- `Ctrl+C` 입력 시 자식이 새 프로세스 그룹의 리더가 되게 하여 포그라운드 잡에만 전달

## [동시성 서버](stock-server)

동시 접속 주식 거래 서버를 두 구조로 구현해 처리율을 비교했습니다.

- **이벤트 기반**: `select`로 소켓 집합을 감시, 단일 흐름이므로 락 없이 자료구조가 안전
- **스레드 풀**: 세마포어로 보호되는 큐 + 워커 20개.
  트리 전체를 잠그면 다른 종목의 거래끼리 막히므로 노드마다 읽기·쓰기 락 분리

측정 결과 스레드 방식이 크게 불리하게 나왔는데, 원인은 클라이언트에 내장된 1초 대기였습니다.
이를 제거하자 두 방식의 차이가 2% 이내로 좁혀졌고, 접속 8개 부근에서 약 14,000 commands/sec으로
함께 포화되어 병목이 동시성 구조가 아니라 네트워크 입출력에 있음을 확인했습니다.
